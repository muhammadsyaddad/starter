1. HTTP CONTRACT (applies to every table)
================================================================================

1.1 Proxy / base URL
  Go CORS allows only :3000 :5173 :8080 + railway prod. Starter runs on :3001.
  -> Do NOT call the backend from the browser directly. Add a Next rewrite:

     // starter/apps/dashboard/next.config.js
     rewrites: async () => [
       { source: "/be-api/:path*", destination: `${process.env.API_ORIGIN}/api/:path*` },
     ]

  Use prefix /be-api, NOT /api — starter owns app/api/mcp/route.ts.
  Env:
    API_ORIGIN               server-side, default http://localhost:8080
                             (prod: https://ramus-erp-be-production.up.railway.app)
    NEXT_PUBLIC_USE_API      "1" = real API; unset = mock rows (replaces current
                             NEXT_PUBLIC_API_URL switch in lib/api.ts)
    NEXT_PUBLIC_TELEMETRY_URL telemetry service for dev tools (T38/T39), default
                             https://tel-api.ramus.asia (separate service, see T38)

  Image URLs: BE returns ABSOLUTE urls built from its own BASE_URL
  (e.g. http://localhost:8080/api/inventory/tools/transactions/photos/<id>).
  Rewrite: take substring after "/api/" and prefix "/be-api/". Or build from id:
    /be-api/inventory/tools/<toolId>/image
    /be-api/inventory/tools/transactions/photos/<photoId>
  These image endpoints are PUBLIC (no token) so <img src> works.

1.2 Auth (JWT)
  POST /auth/login            public
    body   { email*, password* }
    200    { accessToken, refreshToken, access: { pages:{KEY:int}, components:{KEY:int} } }
           NOTE: no "user" key. Call /auth/me right after login.
    401    { error: "invalid email or password" }
    500    { error: "user is inactive" }   (QUIRK: inactive = 500, show message)
  GET /auth/me                JWT
    200    { data: { id, username, email, fullName, role:{id,name}, status,
                     division?:{id,name} }, access: { pages, components } }
  POST /auth/refresh          public
    body   { refreshToken* }
    200    { accessToken, refreshToken }      <- refresh token ROTATES
    401    { error: "invalid refresh token" }
    MUST store the NEW refreshToken every time (old FE didn't -> forced logout on
    2nd refresh). No access map in refresh response (keep previous one / re-call me).
  PATCH /auth/profile         JWT  { fullName?, email?, currentPassword*, newPassword? }
                                   -> { data:<me.data>, message }
  POST /auth/register         perm USERS/W (not needed by tables)

  Lifetimes: access 24h, refresh 7d (Redis). JWT claims: user_id, username,
  role_id, role_name, exp. No email claim.

  Client behaviour to build:
    - store accessToken + refreshToken (localStorage) + mirror access token in
      cookie "auth_token" so Next 16 `proxy.ts` can redirect unauthenticated
      requests to /login
    - every request: Authorization: Bearer <access>
    - on 401 (not /auth/login): ONE in-flight refresh, queue other 401s, retry
      each once; refresh fails -> clear storage + cookie -> /login
    - login page: email + password form -> login -> me -> store user + access ->
      redirect to "/"
    - logout: clear storage + cookie (no BE logout endpoint)

1.3 Permissions (RBAC bitmask)
  READ=1 WRITE=2 DELETE=4 EXECUTE=8.  can(key,a) = (access.pages[key] & a) === a
  Missing key = no access. Old FE also tolerated key case (upper/lower) — do same.
  PAGE keys used by router: USERS ROLE_MANAGEMENT DIVISION SHIP_MANAGEMENT
    INSTALLATION PROBLEM MAINTENANCE DEVICE TOOLS COMPANY GROUP DOCUMENTATION
    TEMPLATE_BUILDER GENERATE_DOCUMENT PROJECTS
  Keys seeded but unused by routes: FINANCE PERMISSION TECHNICIAN DEV_TOOLS
  403 body: { error:"forbidden: your role does not have access to this resource",
              role, resource, action }
  Use can() to: hide sidebar items, hide Add button, hide edit/delete per row,
  guard pages. Spec "perm R/A" annotations == these keys.

1.4 Response envelopes (THREE styles — normalize once)
  (a) { success:true, data, meta? }            errors { success:false, message }
      companies, groups, ships, ship-devices, ship-items, borrowed-tools,
      devices, tools, documentation, folders, templates, submissions
  (b) { meta, data }  (no success key)          errors { error, details? }
      users, divisions, division members, permissions, installations,
      maintenances, projects, surveys
      (installation/maintenance/project/survey DETAIL/CREATE/UPDATE return the
       bare object, no envelope)
  (c) bare array / bare object
      GET role, GET role/:id, role/:id/permission, GET alerts, comments,
      edit-histories, permission search, user search, installations/summary,
      division member detail/update

  meta = { total:int, page:int, limit:int, total_pages:int }
         total_pages is 0 for users, divisions, devices, companies, groups,
         ships, documentation -> compute ceil(total/limit) yourself.
  data may be JSON null instead of [] (tools, tool transactions, templates,
  folder docs, role/:id/permission) -> coerce to [].

  Write:
    unwrap(json) -> { data, meta }  : json.data ?? json  (array/object) ;
                                     meta = json.meta
    errorText(json)                 : json.error ?? json.message ?? statusText
  Delete success bodies vary ({message} | {success,data:{message}} |
  {success,message}) -> treat any 2xx as success, ignore body.

1.5 Pagination / fetch-all
  Starter DataTable paginates CLIENT-side. Backend defaults silently cap lists
  (limit default 10 or 20; old FE never paged -> showed max 10/20 rows).
  Phase 1: fetchAll(path, params) = loop page=1.. with limit=100 until
           collected >= meta.total (or page returned < limit). Endpoints with
           no meta: single call.
  documentation: limit >100 is RESET to 10 -> use limit=100.
  templates: limit=0 crashes (divide by zero) -> always send limit.
  Phase 2 (later, optional): server mode for documentation (T32/T33) only.

1.6 Search / sort / filter conventions
  - Separate search endpoints, param `keyword`: users, divisions, companies,
    groups, ships (all `/…/search`). permissions search uses `name`.
  - documentation: `search`, `sort_title`, `sort_date` (asc|desc).
  - tools requests: `search`, `sort_name`, `sort_date`(latest|oldest), `date`.
  - installations / maintenances: only `sort_order`(asc|desc on created_at),
    `ship_id`, maintenances also `maintenance_type`.
  - projects / surveys: `sort` (asc|desc on created_at), surveys `ship_id`.
  - Everything else (status/type filters, A-Z sort) = client-side.
  Phase 1: since we fetchAll, do search/filter/sort client-side everywhere
  (matches starter DataTable). Exact-match filters (spec 5.1).

1.7 Dates
  Go time.Time -> RFC3339 ("2026-10-20T07:30:00Z"); date-only columns come as
  "YYYY-MM-DD" (installation/maintenance/project) or "YYYY-MM-DDT00:00:00Z"
  (tool borrow_date/return_date). Keep RAW value in the row, format in the cell
  (cells.tsx fmtDate + DATETIME/DATE_MDY/DATE_DMY/DATE_SHORT). Old FE converted
  to "dd/mm/yyyy" strings in mappers -> broke sort. Don't.
  Null date -> "" in row, cell shows "-".

1.8 Enum normalization (BE raw <-> starter lib/enums.ts key)
  Normalize in fromApi, de-normalize in toApi (send what the old UI wrote).
  domain / field                 BE raw values              starter key        write back
  user.status                    active|inactive            "Active"|"Inactive" lowercase
                                                            (starter T01 uses capitalized keys)
  division member status         "Active"|"Inactive"        ACTIVE_INACTIVE    "Active"/"Inactive"
  company.status                 "Active"|"Inactive" (free) active|inactive    "Active"/"Inactive"
  ship.status                    "Active"|"Inactive" (free) active|inactive    "Active"/"Inactive"
  ship.type                      "FMS"|"EMS" (free)         fms|ems (SHIP_TYPE) "FMS"/"EMS"
  ship device/item status        "Active"|"Inactive"        active|inactive    "Active"/"Inactive"
  device.status                  "Active"|"Inactive"        active|inactive    "Active"/"Inactive"
  tool.availability              available|unavailable      starter uses "available"|"not available"
                                                            -> change starter AVAILABILITY to
                                                               {available, unavailable}
  tool tx status                 pending on_loan declined return_pending returned
                                 returned_broke return_rejected      (TX_STATUS, add to enums.ts)
  borrow request status          + partially_approved (overall, BE computed)
  installation.status            scheduled|finish|in_progress|canceled (validated, lowercase)
                                 starter INSTALL_STATUS keys "Scheduled"|"Finish"|"In Progress"|
                                 "Canceled"|"Pending" -> map: scheduled->Scheduled finish->Finish
                                 in_progress->"In Progress" canceled->Canceled ; write lowercase.
                                 "Pending" never exists in BE.
  installation.tipe              "FMS"|"EMS" (free)
  maintenance.status             in_queue in_progress scheduled completed forwarded canceled
                                 (free text, == starter MAINT_STATUS keys) ; "Finish" label = completed
  maintenance.tipe               CORRECTIVE|PREVENTIVE (== MAINT_TYPE)
  maintenance.maintenance_type   remote|dispatch (channel, MAINT_CHANNEL)
  maintenance.severity           URGENT|PRIORITY|NEGLECTIBLE
  project/survey.status          free text; UI uses "Not Started"|"On Progress"|"Done"|"Canceled"
  doc status                     PENDING|ONGOING|FINISHED (== DOC_STATUS)
  doc_type                       CA|FSR|BA|FINANCE|DRAFT (free text, unknown -> muted badge)
  template status                draft|published (lowercase)
  permission resource_type       PAGE|COMPONENT
  Always compare case-insensitively when normalizing.

================================================================================
Current (starter/apps/dashboard):
  lib/api.ts            useResource(resource, mock) — naive REST, no auth
  components/data-table.tsx
                        DataTable (client search/filter/sort/paginate, built-in
                        add/edit FormDialog from `fields`, detail link, `can`)
                        ResourceTable = DataTable + useResource
  components/cells.tsx  index text truncate join twoLine badge dot date idr avatar
                        fmtDate dueDateInfo initials
  lib/enums.ts          ACTIVE_INACTIVE ROLE MAINT_TYPE MAINT_STATUS INSTALL_STATUS
                        DOC_TYPE DOC_STATUS SHIP_TYPE
  components/tables/*.tsx  each table = type + mock[] + <ResourceTable resource=…>

Build:
  lib/http.ts       request(path, init) -> fetch(`/be-api/${path}`), Bearer,
                    401-refresh-retry, unwrap, errorText ; json + multipart
                    (FormData: don't set Content-Type) ; fetchAll(path, params)
  lib/auth.ts       login/logout/me, token storage, AuthProvider + useAuth(),
                    can(key, action) from access map
  app/login/page.tsx, proxy.ts (Next 16 middleware) redirect if no cookie
  lib/resources/<domain>.ts   one ADAPTER per table:
      type Adapter<Row, Raw = unknown> = {
        list: () => Promise<Row[]>           // usually fetchAll + map(fromApi)
        get?: (id: string) => Promise<Row>
        create?: (row: Partial<Row>) => Promise<Row | void>
        update?: (row: Row) => Promise<Row | void>
        remove?: (row: Row) => Promise<void>  // ROW not id: some need short id
        fromApi: (raw: Raw) => Row
        toApi?: (row: Partial<Row>) => unknown // JSON body or FormData
        perm?: string                          // PAGE key for can()
      }
  lib/api.ts        useResource(adapter, mock): if !NEXT_PUBLIC_USE_API -> mock;
                    else list() on mount, refetch after save/remove (simplest
                    correct; BE responses for create/update are inconsistent).
  ResourceTable     prop `resource` becomes `adapter`; pass can() from
                    adapter.perm into DataTable `can` + hide addLabel when !W.

DataTable features the mapping needs but starter lacks (add when wiring the
tables that need them):
  - custom row actions (label, onClick, visibleIf, confirm, perm): Forward (T25),
    Approve/Decline/Return (T14), Restore (T33), Use Template (T34), Details
    modal (T26), Edit members (T03)
  - row selection + bulk actions (T05, T12, T14)
  - page-level selects that change the query (T15 group, T17 company)
  - custom form dialogs (renderDialog already exists) for multipart forms,
    nested selects (company -> ship), technician tag input, item grids (G1-G3)
Starter detail routes differ from old (/ship-data/... vs
/ship-data-management/...) — keep the starter's routes.

5. KNOWN BACKEND QUIRKS / BUGS (work around in FE; list for a BE task)
================================================================================
 5.1  CORS lacks :3001 -> use /be-api rewrite (1.1).
 5.2  Three response envelopes + two error keys (error | message) (1.4).
 5.3  total_pages = 0 on users, divisions, devices, companies, groups, ships,
      documentation. data:null instead of [] on tools, tx, templates, folders.
 5.4  Default limits silently cap lists (10/20) -> fetchAll.
 5.5  sort_order (installations, maintenances) and sort (projects, surveys) are
      concatenated raw into ORDER BY -> SQL injection. FE: only send "asc"|"desc".
 5.6  projects/surveys read `sort`, not `sort_order`; sort is on created_at.
 5.7  Ship list has no company_name/company_id; dropdown-ship alias always "".
 5.8  Company create with group_id:"" -> 400; group_id not updatable.
 5.9  Device create rejects price/qty = 0 (gin required on int).
 5.10 Ship device/item unique_id empty or duplicate -> 500.
 5.11 Ship create installation_date:"" -> 500. Omit when empty.
 5.12 Maintenance routes take MTN short id only; installation routes take uuid or
      INST id. Edit history for maintenance keyed by MTN id.
 5.13 Maintenance create ignores status + severity. Forward = PATCH
      {maintenance_type:"dispatch"} (in place).
 5.14 Installation status validated (scheduled|finish|in_progress|canceled);
      maintenance status free text; "Finish" label means finish vs completed.
 5.15 Tool cancel hard-deletes the transaction (no "cancelled" status).
 5.16 return-request needs TOOLS/X while borrow needs TOOLS/R; partial quantity
      and condition ignored.
 5.17 Users: no last-login data; user detail has no division_id (use division.id).
 5.18 Division search param is keyword (old FE sent q).
 5.19 Permissions CRUD guarded by ROLE_MANAGEMENT, not PERMISSION.
 5.20 Seed (pkg/db/seed.go) missing PAGE keys DOCUMENTATION, TEMPLATE_BUILDER,
      GENERATE_DOCUMENT, TOOLS, PROJECTS -> fresh DB roles can't reach them
      until permissions are added via T04.
 5.21 Templates: limit=0 crash; no route returns version id -> generate flow
      unusable; publish never called by old UI.
 5.22 Documentation main list ignores folders; restore unchecked; total_cost not
      recomputed.
 5.23 Login of inactive user -> 500 not 401. Refresh rotates token.
 5.24 Comments + edit-histories routes have no RBAC (JWT only).
 5.25 Project edit history user always "System" (handler reads userName,
      middleware sets username).
 5.26 Alerts come from a hard-coded external IP poller in alert_service.go.
 5.27 DELETE on a forwarded dispatch maintenance reverts it to remote/in_queue
      instead of deleting (maintenance_service.go DeleteMaintenance).
